# High-Impact News Row — User Guide (v17.60)

The v17.60 HUD adds a **News** row so you can keep a high-impact economic event
in view next to your structure read. Because of a hard platform limitation, this
field is **manual**. This guide explains how to use it and how it could be automated.

---

## 1. How to update the News field manually

1. On the chart, click the **⚙️ Settings** (gear) icon on the *SMC Premium/Discount
   Confluence Engine v17.60* indicator (or double-click any of its drawings).
2. Open the **📰 High-Impact News (v17.60)** input group.
3. Fill in the two fields:
   - **High-Impact News (manual)** — type the event, e.g.
     `USD NFP 8:30am`, `FOMC 2:00pm`, `EUR CPI 5:00am`.
     Leave it blank when there is no relevant event.
   - **News Severity (0=none, 1=low, 2=med, 3=high)** — set the impact level.
4. Click **OK**. The HUD **News** row updates immediately.

### What you'll see on the HUD
| Severity | Colour | Meaning |
|---------:|--------|---------|
| 0 (or blank text) | **Gray** | No active high-impact news (inactive/stale) |
| 1 | **Yellow** | Low impact |
| 2 | **Orange** | Medium impact |
| 3 | **Red** | High impact |

When the text is empty the row reads **"No high-impact news"** in gray.

> **Tip:** Before a known event (e.g. NFP), set the text + severity. Afterward, set
> severity back to `0` (or clear the text) so the row greys out and signals "all clear".

---

## 2. Technical limitation — why it's manual

**Pine Script cannot fetch external APIs or web data.** It runs in a sandbox inside
TradingView and has **no** `http`/`fetch`/network access, no file access, and no way
to read an economic calendar feed. It also cannot detect *when* an input was last
edited, so true time-based "staleness" isn't available — v17.60 models staleness via
the **severity** field (severity `0` = inactive/greyed-out).

This is a platform constraint, not a bug. Any "live news" indicator on TradingView
either (a) requires the user to type it in, or (b) relies on an **external** service
that pushes data onto the chart by some indirect mechanism.

---

## 3. Options for automating the news feed

Listed from simplest to most involved:

1. **Manual discipline (today's default).** Update the two fields at the start of your
   session from a free economic calendar (ForexFactory, Investing.com, Myfxbook).
   Zero setup, fully reliable.

2. **Browser extension / userscript (semi-auto, client-side).**
   A small Chrome/Firefox extension (or Tampermonkey userscript) running in *your*
   browser can scrape a calendar site and **auto-type** the event + severity into the
   indicator's settings dialog via the TradingView UI. No server needed; runs locally.

3. **External companion service (full auto, server-side).**
   A lightweight service (e.g. Python/Node on a small VM or serverless function) polls
   an economic-calendar API, then surfaces the data to you through a channel you already
   watch — a webhook to Discord/Telegram/Slack, an email, or a dashboard — so you can
   mirror it into the field in seconds. (TradingView has no inbound API to write chart
   inputs, so this path informs you rather than editing the chart directly.)

4. **TradingView native economic-calendar widgets.**
   TradingView's *Economic Calendar* panel and the built-in calendar event markers can
   be shown alongside the chart for at-a-glance context, independent of this indicator.

## 4. Want this automated?

**Abacus AI Agent can build the external automation for you** — for example:
- a browser extension/userscript that auto-fills the News fields from a calendar site, or
- a companion service that polls an economic-calendar API and pushes high-impact events
  to Discord/Telegram/email (with severity mapping that matches this HUD's 0–3 scale).

Just ask, and describe which calendar source and notification channel you prefer.

## 5. Quick reference

- Inputs live under group: **📰 High-Impact News (v17.60)**
- `news_manual` — free text (blank = none)
- `news_severity` — `0` none/gray · `1` low/yellow · `2` med/orange · `3` high/red
- HUD location: **News** row (Row 20), always-visible block, above the Debug rows
- Display-only: the news fields **never** affect signals, alerts, or the state machine.
