### Executive Summary

Version 17.56.7 is the most significant architectural upgrade since the Dual Bias Layer (v17.56.0). It introduces a **Dual Mode Alert System** that separates data-collection signals from execution-grade trade calls, adds **session-aware analytics** (London vs NY), fixes **zombie trade classification**, and enforces **strict direction validation** end-to-end from Pine Script through to the frontend dashboard.

| Layer | Key Changes |
|---|---|
| **Pine Script** | Dual mode (DATA/EXECUTION), session detection, hard block rules, direction-zone validation |
| **Backend (Flask)** | v17.56.7 decoder, INVALID classification, zombie prevention, session analytics API |
| **Frontend (Next.js)** | Mode/Session badges, filter controls, session performance panel, INVALID status styling |

**Impact:** Eliminates junk alerts, separates learning data from live trades, enables London-vs-NY performance comparison, and prevents misclassified "LOST" trades that were actually invalid signals.

### 1. Pine Script Updates

**File:** `smc_indicator/smc_pd_v17.56.7.pine`  
**Base:** v17.56.6 (Sniper OTE Upgrade)

#### 1.1 Dual Mode Alert System

Two alert modes gate every signal before it can fire:

| Mode | Session | POI Min | Trend | Guardian | Purpose |
|---|---|---|---|---|---|
| **DATA** | London OR NY | ≥ 3 | Any | Any | Market analysis, pattern collection |
| **EXECUTION** | NY only | ≥ 5 | WITH TREND | CONTINUATION BUY/SELL | Live trade signals |

EXECUTION overrides DATA when both qualify. If neither qualifies, no alert fires.

```pine
string alertMode = na
bool isDataAllowed = isTradeSession and poiScore >= 3 and not blockSignal and not na(alertDirection)
if isDataAllowed
    alertMode := "DATA"
bool isExecutionAllowed = isNYSession and poiScore >= 5 and isWithTrend and isGuardianActive and not blockSignal and not na(alertDirection)
if isExecutionAllowed
    alertMode := "EXECUTION"
```

#### 1.2 Session Detection

Session windows use EST (America/New_York) timezone conversion:

| Session | EST Hours | Purpose |
|---|---|---|
| **London** | 3:00 – 8:00 | European open, higher volatility |
| **NY** | 8:00 – 12:00 | US open, highest liquidity |

Alerts outside both sessions are fully blocked.

#### 1.3 Hard Block Rules

Two absolute blocks prevent junk alerts from ever firing:

```pine
bool blockSignal = poiScore == 0 or actionStep == "INVALIDATED"
```

- **POI = 0:** No confluence whatsoever → blocked
- **INVALIDATED setup:** Zone has been broken → blocked

#### 1.4 Direction Fix — Zone + Bias Validation

Strict three-way validation prevents contradictory signals:

```
LONG requires:  (Demand zone OR Bullish OB) AND HTF ≥ 1 AND LTF ≥ 0
SHORT requires: (Supply zone OR Bearish OB) AND HTF ≤ -1 AND LTF ≤ 0
```

If neither LONG nor SHORT passes validation → `alertDirection = na` → **no alert fires**. This eliminates the previously possible scenario of a "LONG" alert firing while price sits in a Supply zone.

#### 1.5 Updated Alert JSON Payload

```json
{
  "version": "v17.56.7",
  "mode": "EXECUTION",
  "session": "NY",
  "symbol": "EURUSD",
  "direction": "LONG",
  "setup": "A+ SNIPER BUY",
  "poi": 6,
  "align": "WITH TREND",
  "htf_bias": "BULLISH",
  "ltf_bias": "BULLISH",
  "timeframe": "5",
  "entry": 1.08550,
  "sl": 1.08200,
  "tp": 1.09600,
  "valid": true
}
```

New fields: `mode`, `session`, `direction`, `setup`, `align`, `htf_bias`, `ltf_bias`, `valid`.

### 2. Backend Updates (Flask / Railway)

**Directory:** `github_repos/smc-tracker-railway/`

#### 2.1 Database Schema Migration

**File:** `schemas/migrate_v17_56_7_dual_mode.sql`

Added to both `signals` and `opportunities` tables:

| Column | Type | Default | Purpose |
|---|---|---|---|
| `mode` | TEXT | `'DATA'` | Alert mode (DATA / EXECUTION) |
| `session_tag` | TEXT | `'NY'` | Session when alert fired (LONDON / NY) |
| `valid` | INTEGER | `1` | Whether signal passed all validations |

Added indexes: `idx_signals_mode`, `idx_signals_session_tag`, `idx_opportunities_mode`, `idx_opportunities_session_tag`.

**Schema update:** `status` CHECK constraint now includes `'INVALID'`:
```sql
CHECK(status IN ('ACTIVE','WON','LOST','TIMEOUT','GET_OUT','CANCELLED','INVALID'))
```

Migration is **idempotent** — safe to run multiple times on existing databases.

#### 2.2 Trade Classification Fix (Critical)

**File:** `src/tracker/processor.py`

| Condition | Before (v17.56.6) | After (v17.56.7) |
|---|---|---|
| `entry = 0` or `sl = 0` or `tp = 0` | Classified as **LOST** (hits SL immediately) | Classified as **INVALID** (rr=0, pnl=0) |
| Missing price data | Created "zombie" active trades | Marked INVALID on ingestion |

This fix eliminates false losses from data-mode alerts that intentionally lack precise entry/SL/TP.

#### 2.3 Zombie Trade Prevention

**File:** `src/webhook_server/routes.py`

Incoming payloads with `valid: false` are:
1. Logged as informational events
2. **Not stored** in the database
3. Return HTTP 200 with `{"status": "ignored", "reason": "invalid signal (valid=false)"}`

#### 2.4 v17.56.7 Payload Decoder

**File:** `src/oie_processor.py`

- New `normalize_v17_56_7_payload()` function handles the dual-mode JSON format
- Detection: checks for `direction` + `setup` + version fields
- **Direction taken EXACTLY from JSON** — no inference or flipping
- `htf_bias` accepts both string ("BULLISH"/"BEARISH") and numeric codes
- Full backward compatibility with v17.56.6 payloads (defaults: mode=DATA, session=NY, valid=true)

#### 2.5 New API Endpoints

| Endpoint | Method | Description |
|---|---|---|
| `/api/v1/stats` | GET | Performance stats filtered by mode (default: EXECUTION) |
| `/api/v1/session-performance` | GET | London vs NY win rate, avg RR, expectancy comparison |
| `/api/v1/signals` | GET | Now accepts `?mode=` and `?session_tag=` filters |
| `/api/v1/health` | GET | Version v17.56.7, features list in response |

**Stats endpoint filters:**
- `?mode=EXECUTION` (default) — only real trade signals
- `?mode=DATA` — data-collection signals only
- `?mode=ALL` — combined stats
- `?session=LONDON` or `?session=NY`
- `?pair=EURUSD` and `?days=30`

### 6. Expected Improvements — Before vs After

| Metric | Before (v17.56.6) | After (v17.56.7) | Impact |
|---|---|---|---|
| **Junk alerts** | POI=0 and INVALIDATED zones could fire | Hard-blocked at Pine Script level | ~30-40% fewer noise alerts |
| **False LOST trades** | Missing SL/TP → counted as loss | Classified INVALID → excluded from stats | Accurate win rate |
| **Direction conflicts** | LONG could fire in Supply zone | Zone+bias triple validation required | Zero contradictory signals |
| **Performance clarity** | All alerts mixed together | EXECUTION separated from DATA | True trading performance visible |
| **Session insight** | No session tracking | London vs NY comparison dashboard | Optimize session focus |
| **Zombie trades** | Invalid signals stored as active trades | `valid: false` → ignored at ingestion | Clean database |
| **Alert payload** | Basic (symbol, price, setup) | Full context (mode, session, direction, bias, entry/SL/TP) | Rich analytics |
